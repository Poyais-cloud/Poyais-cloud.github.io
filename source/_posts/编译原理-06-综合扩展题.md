本节归集**跨模块的综合题与开放题**，命题人通常用这些题目检测系统性理解能力。常见类型：

- 已实现的小语言（如 TINY）扩展新语法
- 编译器各阶段功能比较与流程梳理
- 给出场景要求设计文法 + 语义动作 + 中间代码生成
- 编译期 vs 解释期、前端 vs 后端的概念辨析

## 1. 编译过程总体流程

### 编译器五阶段

> **Note** 编译器经典流水线
> 1. **词法分析**（Lexical Analysis）：字符流 → 单词流（token stream）
> 2. **语法分析**（Syntax Analysis）：单词流 → 语法树（AST）
> 3. **语义分析**（Semantic Analysis）：语法树 + 符号表 → 带类型注解的语法树
> 4. **中间代码生成**（IR Generation）：语法树 → 三地址码 / 四元组等
> 5. **代码优化 + 目标代码生成**：中间代码 → 优化后中间代码 → 汇编/机器码

### 各阶段输入输出对照

| 阶段 | 输入 | 输出 | 关键技术 |
|---|---|---|---|
| 词法 | 字符流 | 单词流 | 正则、DFA |
| 语法 | 单词流 | 语法树 | 上下文无关文法、LL/LR |
| 语义 | 语法树 | 注解树 | 属性文法、类型检查 |
| 中间代码 | 注解树 | 三地址码 / 四元组 | 语法制导翻译 |
| 优化 | 中间代码 | 优化后的中间代码 | 数据流分析、活跃变量 |
| 目标代码 | 优化后中间代码 | 汇编/机器码 | 寄存器分配、指令选择 |

### 真题

#### [A·三·14]（5 分）简答
> 简述编译过程的主要阶段。

**答案要点**：六阶段（词法、语法、语义、中间代码、代码优化、目标代码）+ 两个贯穿全程的辅助模块（**符号表管理**、**错误处理**）。每阶段简述输入输出（参上表）。

> A. 词法分析的输入是源程序字符流

> C. 中间代码生成发生在语义分析之前

## 2. 编译 vs 解释

### 区别速记

| 维度 | 编译 | 解释 |
|---|---|---|
| 翻译时机 | 一次性翻译完后再执行 | 边读边执行 |
| 输出 | 目标代码（可执行文件） | 无（直接产生执行效果） |
| 执行速度 | 快（已翻译为机器码） | 慢（每行边翻译边执行） |
| 跨平台 | 需重新编译 | 解释器可移植 |
| 代表语言 | C、Pascal、Rust | Python、Lisp、早期 BASIC |
| 错误反馈 | 编译时报告 | 运行时报告 |

### 真题

#### [C·三·14]（5 分）简答
> 编译方式与解释方式的主要区别是什么？

**答案**：见上表。补充说明：
1. 编译方式的核心特征——**生成独立的目标程序**
2. 解释方式的核心特征——**逐句翻译并立即执行，不产生独立目标程序**
3. 现代很多语言混合使用：Java 编译为字节码 + JVM 解释执行（或 JIT 编译）

## 3. 符号表

### 符号表的功能

- 存储**标识符的属性**：类型、作用域、存储位置、参数列表（函数）等
- 跨阶段服务：词法（识别保留字）、语义（类型检查）、代码生成（地址分配）

### 实现方式

| 方式 | 特点 |
|---|---|
| 线性表 | 实现简单，查找 O(n) |
| 二叉搜索树 | 平均 O(log n) |
| 哈希表 | 平均 O(1)，**最常用** |
| 栈式符号表 | 支持作用域嵌套（块结构语言） |

### 真题

#### [D·一·5]（3 分）单选
> 关于符号表，下列说法错误的是（ ）
> A. 符号表用于记录标识符的属性
> B. 符号表只在语义分析阶段使用
> C. 处理嵌套作用域常用栈式符号表
> D. 哈希表是常见的符号表实现方式

**解答**：**答案 B**。符号表在**词法、语法、语义、代码生成**四个阶段都要用。

## 4. 中间代码与代码优化

### 中间代码常见形式

| 形式 | 示例（$A := B + C * D$） |
|---|---|
| 后缀式（逆波兰） | $A\ B\ C\ D\ *\ +\ :=$ |
| 三地址码 | $t_1 := C * D$；$t_2 := B + t_1$；$A := t_2$ |
| 四元组 | $(*, C, D, t_1)$；$(+, B, t_1, t_2)$；$(:=, t_2, \_, A)$ |
| 三元组 | $(*, C, D)$；$(+, B, (1))$；$(:=, (2), A)$（用编号引用） |
| 间接三元组 | 三元组 + 一个间接表（指向三元组顺序） |
| 抽象语法树（AST） | 树形结构 |
| 静态单赋值（SSA） | 每变量恰被赋值一次 |

### 优化层次

- **局部优化**：基本块内（无控制流跳出/跳入的代码段）
- **全局优化**：跨基本块、整个函数内
- **过程间优化**：跨函数

### 真题

#### [B·三·14]（5 分）简答
> 列出至少四种中间代码表示形式。

**答案**：后缀式、三地址码、四元组、三元组、间接三元组、抽象语法树、静态单赋值（SSA）—— 任选 4 种。

---

#### [E·二·12]（4 分）多选
> 下列属于代码优化技术的是（ ）
> A. 常量折叠   B. 公共子表达式消除   C. 循环不变代码外提   D. 死代码消除

**解答**：**ABCD 全选**。

- A 常量折叠：编译期算 $3 + 5$ 直接得 8
- B 公共子表达式：$a*b$ 在两处出现，只算一次
- C 循环不变代码外提：循环体内不变的计算挪到循环外
- D 死代码消除：不可达代码或结果未被使用的语句删除

## 5. TINY 语言扩展（重点扩展题型）

TINY 是龙书提到的一个简单教学语言。考题常以"已为 TINY 实现编译器，现要添加 X 特性"的形式给出。

### 通用 SOP

> **Note** 给小语言加新语法的标准流程
> 1. **写文法产生式**：用 BNF 描述新语法的语法规则
> 2. **影响词法**：是否引入新关键字、新运算符？需要更新词法分析器
> 3. **影响语法分析**：在原文法基础上加入新产生式，重算 FIRST/FOLLOW 或 LR 项目集，检查冲突
> 4. **设计语义**：定义新语法的求值/执行含义；类型规则
> 5. **设计中间代码模板**：写出新语法对应的四元组或三地址码翻译模板
> 6. **测试**：构造典型样例验证

### 真题

#### [B·四·17]（15 分，2020）TINY 加 for 语句
> 已为 TINY 语言构造好 LR(0) 分析表。现在为其加上 `for` 语句：
> $\text{for-stmt} \to \text{for}\ \text{id}\ :=\ E\ \text{to}\ E\ \text{do}\ \text{stmt-list}\ \text{endfor}$
> 要求：(1) 写出此产生式涉及的新项目；(2) 描述分析表需新增哪些状态；(3) 说明对原有 LR(0) 分析表的影响。

**解答**：详见 [04 - LR 分析] 第 5 节"添加新语法到 LR 分析"。

---

#### [C·六·19]（15 分，2021）TINY 加 repeat-until
> 为 TINY 加 `repeat S until E` 语句：
> (1) 写文法产生式；
> (2) 给出语义翻译规则（生成四元组）。

**解答**

**(1) 文法**

$$
S \to \text{repeat}\ S_1\ \text{until}\ E
$$

**(2) 翻译规则**

repeat-until 与 while 的区别：先执行循环体一次，再判断条件。条件**为假时**继续循环、**为真时**退出。

引入标记非终结符 $M$（$M \to \varepsilon$，$M.\text{quad} = \text{nextquad}$）：

文法改写：$S \to \text{repeat}\ M\ S_1\ \text{until}\ E$

**语义动作**：
- $\text{backpatch}(E.\text{falselist}, M.\text{quad})$ —— 条件假回到循环体起点
- $\text{backpatch}(S_1.\text{nextlist}, \text{nextquad})$ —— 循环体执行完进入条件判断
- $S.\text{nextlist} = E.\text{truelist}$ —— 条件真则退出

**翻译模板**（设循环体起于 $L_1$）：

```
L1:    <循环体 S1 的四元组>
       <条件 E 的两条比较四元组>     ← E.truelist 真出口（外部回填）
                                    ← E.falselist 假回到 L1
```

**示例**：`repeat x := x + 1 until x > 10`

```
(100)  (+, x, 1, t1)        ← M.quad = 100
(101)  (:=, t1, _, x)
(102)  (j>, x, 10, ?)       ← E.truelist = {102}（出口）
(103)  (j, _, _, 100)       ← E.falselist 已回填为 100
```

**E.truelist = {102}** 等待外部回填到下一条语句。

> **Tip** repeat-until 比 while 更"自然"地实现"先执行一次再判断"。在四元组层面，它的循环体直接就在最前面，不需要先跳到条件再跳回来。

---

#### [D·六·20]（15 分，2022）TINY 加数组
> 为 TINY 加一维数组（声明 + 引用 + 赋值）：
> (1) 写文法产生式；
> (2) 设计存储分配方案；
> (3) 给出 $A[i]$ 引用的中间代码翻译。

**解答**

**(1) 文法**

```
declare → array id [num]              （声明 A[N]）
exp     → id [exp]                    （数组引用 A[i]）
stmt    → id [exp] := exp             （数组元素赋值）
```

**(2) 存储分配**

声明 `array A[N]`（$N$ 为常量）时：
- 在符号表中为 $A$ 分配一个**基址** $\text{base}_A$
- 预留 $N \times w$ 字节连续空间（$w$ = 单元素字节数）
- 符号表记录：$A.\text{type}$ = 数组、$A.\text{base}$、$A.\text{size}$ = $N$、$A.\text{elemSize}$ = $w$

**(3) $A[i]$ 引用的翻译**

设 $A$ 基址 $a_0$，元素 $w$ 字节，$i$ 是表达式（已翻译完，结果在 $t_i$）。

```
(k)    (*, ti, w, t_offset)         ← 偏移量
(k+1)  (=[], A, t_offset, t_val)   ← 取数组元素：t_val := A[t_offset]
```

数组**赋值** `A[i] := exp`（exp 结果在 $t_e$）：

```
(k)    (*, ti, w, t_offset)
(k+1)  ([]=, t_e, t_offset, A)     ← 数组写入：A[t_offset] := t_e
```

> **Tip** 四元组中数组的两类专用 op：
> - `=[]`：从数组**取**值
> - `[]=`：向数组**存**值
> 这种区分是为后续目标代码生成方便，识别出"读"和"写"两种内存访问模式。

## 6. 矩阵连乘等开放题

某些试卷出"看似与编译原理无关、实则考综合素养"的题，比如矩阵连乘最优顺序——其实是测**子树代价分析**（与代码生成阶段的最优指令选择思想一致）。

### 矩阵连乘动态规划

设矩阵 $A_1, A_2, \ldots, A_n$，$A_i$ 大小 $p_{i-1} \times p_i$。求最优乘法顺序。

DP 方程：$m[i][j] = \min_{i \le k < j}\{m[i][k] + m[k+1][j] + p_{i-1} p_k p_j\}$

复杂度 $O(n^3)$。

### 真题

#### [D·六·21]（15 分，2022 流出）矩阵连乘
> 给四个矩阵 $A_1(10\times 30)$，$A_2(30 \times 5)$，$A_3(5 \times 60)$，$A_4(60 \times 8)$，求最优乘法顺序及最少标量乘法次数。

**解答**

$p_0=10, p_1=30, p_2=5, p_3=60, p_4=8$。

填表 $m[i][j]$（$1 \le i \le j \le 4$）：

**长度 1**（自身，无运算）：
$m[1][1] = m[2][2] = m[3][3] = m[4][4] = 0$

**长度 2**：
- $m[1][2] = p_0 p_1 p_2 = 10 \cdot 30 \cdot 5 = 1500$
- $m[2][3] = p_1 p_2 p_3 = 30 \cdot 5 \cdot 60 = 9000$
- $m[3][4] = p_2 p_3 p_4 = 5 \cdot 60 \cdot 8 = 2400$

**长度 3**：

$m[1][3]$：
- $k=1$：$m[1][1]+m[2][3]+p_0 p_1 p_3 = 0+9000+10\cdot 30\cdot 60 = 27000$
- $k=2$：$m[1][2]+m[3][3]+p_0 p_2 p_3 = 1500+0+10\cdot 5\cdot 60 = 4500$
- min = $\boxed{4500}$（$k=2$，即 $(A_1A_2)A_3$）

$m[2][4]$：
- $k=2$：$m[2][2]+m[3][4]+p_1 p_2 p_4 = 0+2400+30\cdot 5\cdot 8 = 3600$
- $k=3$：$m[2][3]+m[4][4]+p_1 p_3 p_4 = 9000+0+30\cdot 60\cdot 8 = 23400$
- min = $\boxed{3600}$（$k=2$，即 $A_2(A_3 A_4)$）

**长度 4**：

$m[1][4]$：
- $k=1$：$m[1][1]+m[2][4]+p_0 p_1 p_4 = 0+3600+10\cdot 30\cdot 8 = 6000$
- $k=2$：$m[1][2]+m[3][4]+p_0 p_2 p_4 = 1500+2400+10\cdot 5\cdot 8 = 4300$
- $k=3$：$m[1][3]+m[4][4]+p_0 p_3 p_4 = 4500+0+10\cdot 60\cdot 8 = 9300$
- min = $\boxed{4300}$（$k=2$）

**最优结构**：$k=2$ 把 $[1..4]$ 切为 $[1..2]$ 和 $[3..4]$ → $(A_1 A_2)(A_3 A_4)$。

**最少标量乘法**：$\boxed{4300}$ 次。

> **Tip** 这种题的"编译原理意义"：代码生成时，**表达式树的最优代码生成顺序**（最少寄存器、最少访存）也是类似的子树代价 DP（Sethi-Ullman 算法）。命题人挂这道题就是想让你看出"编译器内部到处是 DP"。
